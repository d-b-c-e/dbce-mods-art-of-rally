# Art of Sim Rally 0.4.2 — release draft

**Unpublished.** Prepared from the owner-accepted private rc28 installation,
`0.4.2-rc.28+eb2316dc5bc951557c9bf1f9c2abbe0c6b2118ab.clean`.
This is release text and a preparation plan, not an announcement of a new build.
Public stable remains [0.4.1](https://github.com/d-b-c-e/dbce-mods-art-of-rally/releases/tag/v0.4.1).

## Changes since 0.4.1

- **Shared-profile controls:** use one profile for driving controls, supported
  menu buttons, shortcuts and gears. An existing profile is editable in
  **F6 → Controls → Shared profile**. Choose **Bind from**, Bind an action,
  review the draft and choose **Save bindings**, then restart. The current
  session keeps its active bindings; saved next-start values and unsaved edits
  are shown separately. Cancel ends listening, and Discard removes an unsaved
  draft. Missing/read-only profiles and unavailable devices explain why editing
  is unavailable. A failed Save retains the draft and prior saved bindings.
- **Setup without Wheelkit:** the matching optional Controls Setup download is
  separate from the mod ZIP and stays outside the game folder. It can create
  a missing shared profile. A new device may need setup there or a restart
  before the in-game editor can use it. Public distribution of this private
  companion has not been decided.
- **F6 status and Help:** shared Controls appear first, with readable listening,
  saved, pending-restart and failed-save status. Help has small mod and Wheelkit
  links plus a separate issue/support action. Existing binding, force and
  calibration choices are preserved.
- **Three separate displays:** select the equal-size displays immediately left
  and right of the primary, and check their activation windows before rendering
  side views. An extra dashboard display is excluded. The old stored display
  indices are preserved but no longer used to choose the sides.
- **Frame rate:** optional on-screen fps display and Cameras-page average,
  1% low and worst-frame readouts.
- **Additional action routes and prompt fallback:** shared horn, look back and
  recover-car routes, plus Art-local repair/quick-restart/look bindings. Recover
  uses the game's one-second hold. Wheel button prompts use a text fallback
  where the game has no matching artwork. These action/glyph responses remain
  separately untested on hardware; they are not new acceptance claims.

Force behavior and saved tuning are retained. Camera keys and the crash rattle
already shipped in 0.4.1: camera defaults remain 8/2 forward/back, 9/3 up/down,
4/6 left/right, 7/1 tilt down/up, +/- field of view and 5 reset. The crash cue retains
its 120 ms push plus a 25 Hz half-magnitude rattle lasting 250 ms with 150 ms fade;
a wheel that rejects the rattle keeps the push alone. Existing custom keys and
effect strengths are preserved. No force retuning is part of this preparation.

## Install, update and return to an older version

For 64-bit Windows, with Unity Mod Manager 0.27.0 or newer already installed for
Art of Rally. The Steam build is the documented target; other stores are not
confirmed. Close the game, extract the chosen mod ZIP into a fresh folder and
run its `Install.bat`; do not use GitHub's Source code archive. The installer
verifies the package and installed payload hashes, including both native copies.
Settings, bindings, triple geometry and unknown user files stay in place.

Keep the previous ZIP. Before updating, back up `Settings.xml`, `TripleScreen.xml`,
`desired-layout.json` and `dbce-controls.ini` from `Mods/ArtOfSimRally` if present.
The installer does not create a backup or automatically roll back a partial
copy failure. Keep the game closed after a failed copy until the full install
succeeds or the previous package is restored.

To return from a shared-input candidate to 0.4.1 or another older package, run
the **shared candidate's Uninstall.bat first**, then install the older ZIP.
An older installer does not know about `dbce_shim.dll`. The current uninstaller
removes it only when the installed build record owns its current bytes; changed
or manually placed copies are retained. Settings and profiles remain, and
restoring earlier settings is a separate deliberate action. Keep newer owner
choices unless reverting them is intended. See [Setup](../SETUP.md).

## Acceptance and known limits

On October18 the owner declared the currently used rc28 installation done and
ready to release. Preserve accepted gameplay, force and performance evidence.
The retained production build/release verifier (353 assertions), isolated installer
(64 assertions), owner upgrade/closure and PS5.1 companion PlanOnly records are in
[Local deployment](../LOCAL-DEPLOYMENT.md). These were read, not rerun for this
documentation. The 64-case rollback fixture used rc27, not public 0.4.1.

Visible Bind listening/Cancel, Save refusal, readable error persistence and
Discard have narrow retained observation evidence. Separately untested extras
remain **moved-control/new-device successful Bind → Save → restart, action
response, glyphs and device loss on hardware**. This draft does not convert
them into new blockers or claim they passed. Recorder, research probe and
SessionTools remain separate development tools, excluded from the mod ZIP.

## Owner decision and release preparation

The exact decision still needed is **whether to publish the pinned shared-input
shim binary and its source provenance, and whether to distribute the separate
optional Controls Setup companion**. This follows the existing explicit scope in
`lib/input-shim/PROVENANCE.md` and [Releasing](../RELEASING.md); accepting the game
installation did not settle those public-distribution choices. No publication
authorization or choice is inferred here.

After that decision, the coordinator can assign public packaging/provenance
preparation. The current producer refuses a stable shared-input build and a
stable build with the current local toolkit pin. Leave both checks intact until
that separate work is assigned. Do not relabel the accepted ZIP, fake an official
pin, substitute a native DLL or silently choose a baseline flavor without shared
input. Keep the exact rc28 archive and receipts immutable.

For a future candidate/final artifact, use one affected local package/check batch
through the existing coordinator runner, record its own source/hash identity and
review the packaged text/notices. Documentation changes alone require no gameplay,
force or performance repeat. Installation, runtime work and public publication
remain separate actions. Once authorized, publish the exact validated assets
and checksum at their recorded source commit, then download/hash-check them.
