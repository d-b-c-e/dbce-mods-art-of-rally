## Confirmed code defect: KI-20

Inspection of build 17584229 shows that `GameEntryPoint.EventManager` creates a
manager when its private `eventManager` field is null. Its getter excludes scene
index 1; the game's own Update excludes indexes 1 **and 3**. It is not a passive
state accessor usable from a persistent menu watchdog.

`EventManager` construction attempts scene-dependent setup. Its exception handler
starts a ghost replay request before logging the failed construction. Derived
Freeroam construction then throws, leaving the singleton unassigned. Our state
checks catch that exception and retry next frame. Ghost completion can enter the
same getter, amplifying the work. These read paths exist in 0.2.3; RC4 added a
diagnostic state read, so this is not evidence of a wholly new RC4 defect.

The correction reads the existing private field through cached reflection metadata.
It never calls the lazy getter and never caches a manager across stage teardown.
Input and support access use the same path. Missing state keeps force/telemetry
parked and leaves the game's input untouched. No game manager creation logic,
leaderboard code, physics, assist, FFB tuning or toolkit binary is changed.
