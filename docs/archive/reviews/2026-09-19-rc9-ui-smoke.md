## Cause and successor scope

Local assembly inspection found UMM's blocking Canvas intercepts raycasts but
the game's `RewiredStandaloneInputModule.Process` still dispatches navigation,
submit and cancel. `PanelManager.Update` separately polls back/cancel actions.
An IMGUI `Event.Use()` cannot consume those reads.

The successor guards those actual dispatch paths and the native Mods panel.
Pause/replay input reads are guarded without skipping their other update work.
No Rewired maps, input backend, manager factories or physics are changed.
Closing retains ownership through held keyboard/mouse, native UI action/axis,
and USB Settings input, focus/readiness, then two neutral frames. Cached native
pointer presses/drags are discarded without erasing keyboard selection. The
USB reader runs before Settings shortcuts on the early watchdog update.

Independent review caught missing replay scrub axes24/25 in the close barrier.
The correction tracks only axes/buttons actually polled by the guarded native
context, so active scrubbing waits for release without unrelated resting pedals
trapping the stock menu. Fixtures cover both held axes, including0.05 travel,
release and leaving the replay context. Source review is not physical acceptance.

The first RC10 gate (`a90288b`, run
`rc-0.2.6-rc.10-18a03b835d014972a4f2fa0a2baf918f`) stopped before packaging:
the lifecycle fixture lacked Unity's `DefaultExecutionOrder` attribute double.
Adding that test-only declaration restores the64-assertion lifecycle suite;
the failure receipt remains retained and a fresh complete gate is required.

Text scaling is scoped to a cloned skin for this mod's content. Auto uses2x at
2160p when UMM is at its1x default; nondefault UMM scaling takes precedence.
Help offers **Use UMM scale** to explicitly choose1x. Explicit UMM width/height
preferences constrain content. UMM chrome, Params.xml and other mods' styles
remain owned by the host. This needs a real screenshot, not just size-policy tests.
